## Phase 1: Google Cloud API Enable Checklist

The following Google Cloud APIs MUST be enabled (user needs to do this manually):
1. **Places API (New)** — already in use for text/nearby search
2. **Maps JavaScript API** — needed for Google Maps rendering (migration from Leaflet)
3. **Directions API** — driving/walking routes between places
4. **Distance Matrix API** — distance/time estimates for multiple waypoints
5. **Geocoding API** — address/location name → coordinates
6. **Street View Static API** — 360° preview images for popular places

**Billing:** Must have billing account linked to the GCP project with the above APIs enabled.

## NEW Phase 14: Gemini 503 High-Demand Fallback

### Problem:
`gemini-3-flash-preview` model often returns `503: This model is currently experiencing high demand`. Preview models are unstable.

### Fix — Model Fallback Chain:
```
gemini-3-flash-preview → (503?) → gemini-1.5-flash → (fails?) → gemini-2.0-flash
```

### Implementation (`src/lib/gemini.js`):
- Create a `generateWithFallback(prompt)` function that tries models in order
- Catch 503 errors → retry with next model
- Log which model succeeded for debugging
- Update all 3 functions (`getPlaceInfo`, `getPopupDescription`, `getNearbyRecommendations`) to use it

### Implementation (`src/app/api/ai-guide/route.js`):
- Same fallback chain in the API route
- Return better error message when ALL models fail

## NEW Phase 16: Multi-User Device Isolation (No Login)

### Problem:
3 people using same browser (e.g., shared computer) see each other's saved routes & selected places. All `localStorage` is global per browser.

### Solution — Device ID prefix:
- On first load, generate a **device ID** using `crypto.randomUUID()` (secure unique ID)
- Store device ID in `sessionStorage` (per-tab, clears on close) OR `localStorage` with user selection
- Prefix ALL Zustand persist keys + localStorage keys with this device ID

### Implementation:
1. **`src/hooks/useDeviceId.js`** — generates/stores a unique device ID
2. **`src/store/useTravelStore.js`** — read device ID, use it as storage name prefix
3. **`src/app/saved/page.js`** — load routes from device-specific localStorage key
4. **`src/app/route/page.js`** — save routes with device-specific key

### Storage structure:
```
localStorage:
  └── kgc-device-id: "abc123-uuid"
  └── kgc-travel-storage-abc123: { selectedPlaces, savedRoutes }  ← device-specific
  └── kgc-saved-routes-abc123: [...]                               ← device-specific
```

### User flow:
- Your device = automatically gets unique ID
- Your routes, saved items = only visible on YOUR device
- Another person's device = different ID → sees ONLY their own data
- `sessionStorage` based → clearing browser session resets isolation

## NEW Phase 17: Live Tracking Dashboard

### Feature: Real-time travel monitoring
When user has a route loaded and starts traveling, show a live tracking panel:

### Data to display:
| Metric | Source |
|--------|--------|
| **Current location** (blue dot, moving) | `useUserLocation` hook (GPS watch) |
| **Direction/heading** (compass arrow) | `heading` from GPS + device orientation |
| **On route check** (green ✓ / red ✗) | Compare current location vs route polyline |
| **Km travelled** | Cumulative GPS distance since route started |
| **Km remaining** | Distance Matrix from current location → final destination |
| **ETA** | Remaining time based on Distance Matrix API |

### Implementation:
1. **`src/hooks/useLiveTracking.js`** — aggregates GPS + route data
   - `travelledKm`: sum of GPS point-to-point distances
   - `remainingKm`: Distance Matrix API call from current → last waypoint
   - `onRoute`: check if current position is near route polyline (within 100m tolerance)
   - `eta`: estimated arrival time = now + drive time

2. **`src/components/layout/LiveTrackingBar.jsx`** — collapsible bottom bar
   ```
   ┌─────────────────────────────────────────────────────────┐
   │ 📍 মিরপুর, ঢাকা  →  🧭 NW (315°)  →  ✓ রুটে আছেন        │
   │ 🛣️ 12 km travelled  │  🎯 48 km বাকি  │  ⏱️ ETA 2:15 PM  │
   └─────────────────────────────────────────────────────────┘
   ```

3. **Distance from route polyline** — use `google.maps.geometry.spherical.computeDistanceBetween()` or manual calculation
