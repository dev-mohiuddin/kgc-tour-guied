# Plan: Google Places API + Discover Feature Integration

## Overview
Integrate Google Maps JavaScript API with **Places Library** (`PlacesService`) into the existing KGC Smart Voyager Next.js project. Create a new **Discover** page where users can find tourist attractions near any Bangladesh location (division, district, or upazila) via Google Places API, with markers and InfoWindows.

---

##  Data Available
- **`src/locales/places-in-bangladesh/`** — Full Bangladesh geo hierarchy:
  - `divisions/divisions.json` — 8 divisions with `id`, `name`, `bn_name`
  - `districts/districts.json` — 64 districts with `division_id`, `name`, `bn_name`, `lat`, `lon`
  - `upazilas/upazilas.json` — 500+ upazilas with `district_id`, `name`, `bn_name`
  - `unions/unions.json` — 4500+ unions with `upazilla_id`, `name`, `bn_name`
- Districts have `lat`/`lon` coordinates → can center map automatically
- No `lat`/`lon` in upazila/union data → will use **Google Places Text Search** to geocode + find attractions
- Existing MongoDB `Place` model has `coordinates: { lat, lng }` with `2dsphere` index

##  Files to Create / Modify

### 1. New File: `src/lib/places-utils.js` [NEW]
**Purpose:** Utility functions for Google PlacesService operations (client-side).

```js
// Functions:
- getNearbyAttractions(map, center, radius, type) → Promise<PlaceResult[]>
  // Uses google.maps.places.PlacesService.nearbySearch()
- getAttractionsByText(map, query) → Promise<PlaceResult[]>
  // Uses google.maps.places.PlacesService.textSearch()
  // For district/upazila-level searches + 5-6 hour drive range
- getPhotoUrl(photoReference, maxWidth) → String
  // Builds Places photo URL with API key
- geocodePlaceName(name) → Promise<{lat, lng}>
  // Uses Geocoder to convert place name to coordinates
```

### 2. New File: `src/components/map/PlacesMapComponent.jsx` [NEW]
**Purpose:** Standalone map component for the Discover page — separate from the existing route-planning MapComponent.

Props:
- `center` (default: Dhaka `{ lat: 23.8103, lng: 90.4125 }`)
- `radius` (default: 10000m for 10km)
- `locationName` — display label for current location
- `onPlaceSelect(place)` — callback when user clicks a marker

Features:
- Initializes Google Map centered on the provided location
- Uses `PlacesService.nearbySearch()` to find `tourist_attraction` type places within radius
- Custom markers with numbered pins (matching existing style)
- **InfoWindow** on marker click showing:
  - Place name, rating (stars emoji), photo thumbnail, vicinity
  - "View Details" button
- Loading spinner while places load
- Error state

##  Google Maps API Key Configuration

### In `.env.local`:
```
NEXT_PUBLIC_GOOGLE_MAPS_API_KEY=your_api_key_here
GOOGLE_MAPS_API_KEY=your_api_key_here
```

### Required APIs in Google Cloud Console:
- Maps JavaScript API
- Places API (new)
- Geocoding API

### Map script includes `libraries=places` automatically via `@googlemaps/js-api-loader`:
```js
googleMapsLoader.importLibrary('places')
googleMapsLoader.importLibrary('marker')
googleMapsLoader.importLibrary('maps')
googleMapsLoader.importLibrary('routes')
```

##  Data Flow

```
User selects Division → load districts JSON
  → User selects District → get lat/lon from district JSON
    → Map centers, runs PlacesService.nearbySearch(lat, lon, radius, 'tourist_attraction')
      → Google returns up to 60 results
        → Markers + InfoWindows on map
        → Result cards below
          → "Add to Route" → useTravelStore.addPlace()
```

---

##  Error Handling
- No API key → show config message
- Places API error → show retry button
- Empty results → show "no attractions found" + suggest wider radius
- Geocoding failure → fallback to district JSON coordinates
- No internet → show offline message
